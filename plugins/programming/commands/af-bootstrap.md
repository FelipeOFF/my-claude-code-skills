# /af-bootstrap — scaffold a new Flutter app

Use this to stand up a **brand-new** app in this architecture, or to lay the
foundational rings (tree + DI bootstrap + main wiring) into an empty Flutter
project. For a single feature in an app that already exists, use `/af-feature`.

## Read exactly one reference

Read ONLY `skills/absolute-flutter/references/01-architecture.md`. It is the
spine: folder tree, the inward dependency rule, DI bootstrap order, and the
`main.dart` / `app_widget.dart` wiring. Pull in `_conventions.md` only if you
are unsure of a naming rule. Do not read the other eleven references unless the
user asks you to also generate that layer's internals.

## Steps

1. **Lay the tree.** Copy `assets/templates/app_scaffold/tree.md` and create
   `lib/` exactly as it describes (empty folders are fine). Package name is
   `app`; every import is `package:app/...`.
2. **Drop the entry points.** Copy `assets/templates/app_scaffold/main.dart` and
   `app_widget.dart`. Rename the `App*` anchors only if the app prefixes differ.
   Keep `main.dart` to bootstrap-only.
3. **Pubspec + codegen.** Merge `assets/templates/config/pubspec.partial.yaml`
   into `pubspec.yaml`, and copy `analysis_options.yaml` + `build.yaml` to the
   project root. These enforce package-imports lint and the 120-col formatter.
4. **Stand up the inner ring first** in this DI order: environment → database →
   gateway → service → repository → domain → features. Each binding may
   `it()`-resolve only what is registered before it. The bindings themselves
   come from `/af-di`; build them in this order.
5. **Add the error model + use-case base** (`domain/app_error.dart`,
   `domain/abstract_use_case.dart`) — nothing above the domain compiles without
   these. Generated by `/af-usecase`.
6. **Wire transport** (`AbstractGateway` + `LoggedClient`/`NonLoggedClient` +
   `DioException.asAppError()`) — generated by `/af-gateway`.
7. **Add design system + router** so `app_widget.dart` resolves: `AppColors` /
   `AppText` (`/af-design-system`) and `AppRouter` (`/af-navigation`).
8. **Add the first feature slice** with `/af-feature`.

## Wire / verify

- `await AppDI.setupDI()` (or the two-phase setup) must complete BEFORE
  `runApp` in `main.dart`.
- `app_widget.dart` holds NO logic — only theme + `routerConfig: AppRouter.config`.
- Run `dart run build_runner build --delete-conflicting-outputs` after any DTO
  exists, then `flutter analyze`.
